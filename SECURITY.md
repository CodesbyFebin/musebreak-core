# Security policy

MeTaBoss is an experimental development project, not a production-qualified system. No released version is promised security support or an incident-response SLA.

The new /business guarantee does not cover legacy /os task routes, demo orders, prototype hardware, model providers, or the hash-commitment MVP. See [the security wiki](docs/wiki/Security.md) and [workflow assumptions](docs/verification/INVOICE-WORKFLOW.md).

## Reporting a suspected issue

Use GitHub's private vulnerability reporting **if the repository offers it**. Check the Security tab first; this policy does not claim that private reporting has been enabled. If unavailable, open only a minimal public issue asking for a private contact route, without exploit details, credentials, customer records, private keys, or personal information. No private email address or bounty program is advertised here.

Include affected revision, synthetic reproduction, expected/actual behavior and relevant boundary. Do not test against other people's systems or real customer databases. Rotate exposed credentials through their issuing systems. Do not post them in an issue to request rotation.
